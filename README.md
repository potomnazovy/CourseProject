# Многопоточный агрегатор данных из REST API (Этап 2)

Курсовая работа по дисциплине «Объектно-ориентированное программирование».  
**Этап 2**: Spring Boot-приложение, которое параллельно и периодически опрашивает открытые REST API, приводит ответы к единой модели, сохраняет их в файл (JSON или CSV) и управляется через собственный REST API.

## 🛠 Используемые технологии

- **Java 21** (включая `java.time`, `java.net.http.HttpClient`, `java.util.concurrent`)
- **Spring Boot 3.2.0** (REST API, Dependency Injection, управление жизненным циклом бинов)
- **Gradle** (система сборки с автоматической проверкой качества кода)
- **Gson** (парсинг и сериализация JSON, кастомные адаптеры для `LocalDateTime`)
- **SLF4J + Logback** (логирование с выводом в файл и консоль)
- **Java NIO** (потокобезопасная работа с файловой системой: `Files`, `Path`)
- **JUnit 5 + Mockito + MockMvc** (модульное и интеграционное тестирование)
- **JaCoCo** (контроль покрытия кода тестами, строгий порог ≥ 70%)

## 🌐 Выбранные API

В проекте используются три открытых API, не требующих ключей авторизации. Все они удовлетворяют требованиям задания (JSON-ответ с вложенными объектами/массивами, поддержка query-параметров, данные изменяются со временем):

1. **Open-Meteo** (`weather`)
    - *Описание:* Прогноз погоды. Возвращает текущую температуру, скорость ветра и почасовой прогноз.
    - *Параметры:* `latitude`, `longitude`, `current`, `hourly`.
2. **Frankfurter** (`currency`)
    - *Описание:* Актуальные курсы валют от Европейского центрального банка.
    - *Параметры:* `base`, `symbols`.
3. **CoinGecko** (`crypto`)
    - *Описание:* Текущие цены и рыночные показатели криптовалют.
    - *Параметры:* `ids`, `vs_currencies`, `include_market_cap`, `include_24hr_vol`.

## 🏗 Архитектура и формат

### Структура проекта
Проект строго разделен на слои для соблюдения принципов **SOLID** и **Separation of Concerns**:

- **`controller`** — тонкие REST-контроллеры (`PollingController`), делегирующие бизнес-логику сервисам. Не содержат HTTP-запросов к внешним API.
- **`core`** — бизнес-логика. `SchedulerService` управляет пулом потоков (`ExecutorService`) и жизненным циклом опроса. `AggregateService` отвечает за непосредственный опрос и маппинг.
- **`source`** — паттерн Стратегия. Интерфейс `ApiSource` и его реализации (`WeatherSource`, `CurrencySource`, `CryptoSource`). Новый API добавляется без изменения существующего кода (Open/Closed Principle).
- **`storage`** — потокобезопасные (`synchronized`) реализации интерфейса `Storage` для JSON и CSV, а также `StorageFactory`.
- **`http`** — абстракция `HttpClient` и его реализация `JavaHttpClient` (легко мокается в тестах).
- **`model`** — единая модель `AggregatedRecord` и DTO для входящих запросов (`StartRequest`, `QueryParams`).
- **`config`** — сборка бинов и конфигурация по умолчанию (`AppFactory`).

### Ключевые особенности реализации:
- **Единая модель:** Все разнородные ответы API приводятся к плоской структуре `AggregatedRecord` (источник, параметр, поле, значение, время).
- **Многопоточность:** Пул потоков `Executors.newFixedThreadPool(n)` опрашивает API параллельно. Интервал между повторными опросами одной и той же задачи регулируется параметром `t`.
- **Отказоустойчивость (Fault Tolerance):** Сбой или таймаут одного источника не прерывает опрос остальных. Поток логирует ошибку и корректно засыпает, предотвращая перегрузку CPU (busy wait).
- **Graceful Shutdown:** Благодаря аннотации `@PreDestroy`, при остановке Spring-контекста все фоновые non-daemon потоки корректно прерываются через `shutdownNow()`, данные не теряются.
- **Тестирование:** Сетевые вызовы изолированы (Mockito), контроллеры проверены через MockMvc, многопоточная логика стабилизирована (использование `CountDownLatch`/`Awaitility` вместо ненадежных `Thread.sleep` в ассертах).

## ⚙️ Конфигурация (`application.yml`)

Настройки вынесены в конфигурационный файл. Для каждого API в коде (`AppFactory`) задано **минимум 2 набора параметров** (например, разные города или валютные пары), а параметры многопоточности и путей берутся из файла:

```yaml
app:
  default-n: 3
  default-t: 10
  default-file-path: data.json
  default-format: json
  default-mode: append
  default-apis: weather,currency,crypto
```

## REST API
### Приложение предоставляет следующие эндпоинты для управления опросом и просмотра данных.

### 1. Запуск опроса
```HTTP
POST /polling/start
```
#### Запускает параллельный опрос источников. Все поля в теле запроса необязательны. Если поле не передано, используется значение по умолчанию из application.yml. Если для источника передан свой список параметров, он полностью заменяет набор из конфигурации.
#### Пример запроса:
```bash
curl -X POST http://localhost:8080/polling/start \
  -H "Content-Type: application/json" \
  -d '{
    "n": 4,
    "t": 15,
    "format": "csv",
    "file": "custom_data.csv",
    "mode": "create",
    "sources": {
      "weather": [
        { "latitude": "40.71", "longitude": "-74.00" }
      ]
    }
  }'
```

#### Возможные ответы:
- **200 OK** — опрос успешно запущен.
- **409 Conflict** — опрос уже запущен.
- **400 Bad Request** — неверные параметры (например, n <= 0).

### 2. Остановка опроса
```HTTP
POST /polling/stop
```
#### Останавливает текущий опрос, завершает потоки и освобождает ресурсы.

#### Пример запроса:
```bash
curl -X POST http://localhost:8080/polling/stop
```

#### Ответ: **200** OK — опрос остановлен.

### 3. Статус опроса
```HTTP
GET /polling/status
```

#### Возвращает текущий статус планировщика.

#### Пример запроса:
```bash
curl http://localhost:8080/polling/status
```

#### Ответ (JSON):
```json
{
  "running": true
}
```

### 4. Просмотр данных
```HTTP
GET /polling/data
```

#### Возвращает содержимое файла с результатами опроса. Поддерживает опциональный фильтр по источнику.

#### **Пример запроса (все данные):**
```bash
curl http://localhost:8080/polling/data?format=json&file=data.json
```

#### **Пример запроса (только cryptocurrency):**
```bash
curl "http://localhost:8080/polling/data?source=crypto&format=json&file=data.json"
```

### Логирование

#### Каждый опрос логируется в файл logs/app.log и консоль с точностью до миллисекунд. Формат строго соответствует заданию: начало [START] и завершение [END] (успех, ошибка или таймаут).

#### **Пример вывода:**
```text
14:32:01.120 [pool-1-thread-1] INFO  o.e.core.SchedulerService - [START] weather {latitude=52.52, longitude=13.41}
14:32:02.450 [pool-1-thread-1] INFO  o.e.core.SchedulerService - [END] weather OK
14:32:02.455 [pool-1-thread-2] ERROR o.e.core.SchedulerService - [END] crypto ERROR (Runtime): Timeout
```

### Формат данных

#### Каждая запись в JSON/CSV имеет единую плоскую структуру AggregatedRecord. Это позволяет унифицировать хранение разнородных данных.

#### **Пример записи в JSON:**
```json
{
  "source": "weather",
  "param": "52.52;13.41",
  "field": "temperature_2m",
  "value": 15.5,
  "timestamp": "2026-11-20T14:32:02"
}
```

#### **Пример записи в CSV:**
```csv
source,param,field,value,timestamp
weather,52.52;13.41,temperature_2m,15.5,2026-11-20T14:32:02
currency,USD,EUR,0.92,2026-11-20T14:32:03
crypto,bitcoin,usd,65000.0,2026-11-20T14:32:04
```
